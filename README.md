# Steam Wrapped

Инструмент, который честно расскажет, куда ушли годы. `mormyszka` — только демо-профиль на главной странице.

Одностраничная статистика Steam-профиля: часы, топ игр, жанры, бэклог-рулетка
и генератор PNG-карточки. Чистые HTML/CSS/JS без фреймворков, сборки и CDN —
страница целиком статическая и живёт на GitHub Pages.

**Живая версия:** https://kyuuketsukiakado.github.io/steam-wrapped/
(старый адрес `…/Steam_Checker/` редиректит сюда сам)

---

|---|---|
| Шапка | ник, аватар и три главные цифры: игр в библиотеке, часов всего, часов за 2 недели |

## Стек

Ноль зависимостей: HTML, CSS (кастомные свойства, grid, `IntersectionObserver`),
ванильный JS. Шрифты **Unbounded** и **Manrope** (variable, OFL) лежат
локально в `assets/fonts` — внешних запросов страница не делает вообще.

### Словарь жанров лежит в репозитории

`assets/data/genres.json` — это **не кэш**, его нужно коммитить. Магазин Steam
не отдаёт жанры пачкой, только по одной игре, и на общих IP GitHub Actions
быстро отвечает `429 Too Many Requests`. Поэтому один раз узнанные жанры
хранятся в репозитории и переиспользуются всеми прогонами и всеми профилями.

Порядок поиска: словарь → локальный `.cache/` → магазин → SteamSpy. Пустые
ответы не сохраняются, чтобы следующий запуск попробовал снова. Файл
пополняется сам, по строке на игру — диффы читаются глазами.


### Общие правила для всех профилей

`assets/data/rules.json` — второй файл, который тоже **коммитится**. В нём
лежат исключения служебного софта, чистка названий, перевод/исключение жанров
и игровые единицы для блока «главная игра жизни». Его читает `fetch_data.py`,
а браузер применяет тот же контракт к будущим живым профилям. Поэтому Dota
остаётся матчами, Stardew — фермерскими днями, а неизвестная игра получает
нейтральный пересчёт в вечера.

Проверки перед изменением правил:

```bash
python tools/selftest.py
node tools/test_profile_data.js
```

`node` нужен только для этой дополнительной проверки разработчику; самому
сайту, Python-сборщику и GitHub Pages он не требуется.

## Обновить данные

```
echo "КЛЮЧ_С_steamcommunity.com/dev/apikey" > steam_key.txt
python fetch_data.py --user K_Ak4d0
```

Скрипт резолвит ник в SteamID64, забирает библиотеку и активность через
Steam Web API, качает аватар и перезаписывает `assets/js/data.js`
(компактно: одна игра на строку). Дальше — интересное:

* **жанры** берутся из store-эндпоинта `appdetails` (неофициальный, поэтому
  с паузами, ретраями и файловым кэшем в `.cache/`). Если магазин молчит —
  например, у игр с возрастным гейтом (Cyberpunk, Ведьмак, DOOM, Metro) —
  скрипт падает в фолбэк на **SteamSpy**. Пустые результаты **не кэшируются**:
  следующий прогон попробует снова;
* **метки магазина не жанры**: «Free to Play», «Ранний доступ», «18+»,
  «Утилиты» выкидываются (когда-то Free to Play съедал 1321 час доната);
* **служебный софт** (Wallpaper Engine, ShareX, Jackbox Megapicker) и тестовые
  ветки (`test server`, `dedicated server`, `(beta)`, `sdk`, `benchmark`)
  в статистику не попадают;
* **названия чистятся** от `™` и суффиксов «Complete Edition» / «Enhanced Edition»;
* **`extra_games.json`** подмешивает то, что API не отдаёт совсем: Dota 2
  попала в игнор-лист магазина, её часы взяты из отзыва и вписаны руками;
* **часы по жанрам** (`genreHours` в data.js) считаются по всей библиотеке:
  часы игры делятся поровну между её жанрами — донат на странице использует
  именно их.

Полезные флаги: `--dry-run`, `--steamid`, `--delay 3`, `--max-details 200`,
`--refresh-genres`, `--extra 0` (игнорировать extra_games.json),
`--profile` (собрать страницу друга).
Подробности и разбор ошибок — в [ИНСТРУКЦИЯ.md](ИНСТРУКЦИЯ.md).

Проверить скрипт без ключа и интернета: `python tools/selftest.py`.

## Автообновление через GitHub Actions

Руками запускать скрипт больше не обязательно — это делает GitHub.

**Один раз** нужно положить ключ в секреты репозитория:
`Settings → Secrets and variables → Actions → New repository secret`,
имя — `STEAM_API_KEY`, значение — сам ключ. Секрет виден только Actions,
в коде и логах его нет.

| Workflow | Когда | Что делает |
|---|---|---|
| **Обновить мою статистику** | каждый день в 04:20 UTC + кнопка | тянет свежие данные, перерисовывает og-картинку, коммитит если что-то изменилось |
| **Собрать карточку друга** | кнопка с полем ввода | собирает страницу для чужого профиля и печатает ссылку на неё |

Запуск руками: вкладка **Actions** → нужный workflow слева → **Run workflow**.

### Карточка для друга

В поле ввода — SteamID64 (17 цифр), ник или ссылка на профиль. Друг ничего
не устанавливает: ни форка, ни своего ключа, только SteamID. Результат —
страница `u/<steamid>/` и ссылка на неё в сводке запуска.

Что важно:

* профиль должен быть **открыт** (Настройки приватности → «Игровые данные» =
  Открытый доступ). Если закрыт, workflow ответит понятным сообщением,
  а не стектрейсом;
* `extra_games.json` — личный файл владельца (там Dota), чужим профилям
  он не подмешивается;
* GitHub Pages обновляет сайт минуту-другую после коммита.

## Безопасность

Ключ API читается в таком порядке:

1. флаг `--key` (разово, для отладки);
2. переменная окружения **`STEAM_API_KEY`** — так работает GitHub Actions;
3. файл `steam_key.txt` — запасной вариант для локальных прогонов.

`steam_key.txt` прописан в `.gitignore` и в репозиторий не попадает. В логи
ключ не пишется вообще: адреса запросов обрезаются до пути, а всё похожее
на ключ маскируется — логи Actions публичны. В `data.js` уезжают только
публичные данные профиля: названия игр, часы и жанры.

### Если ключ отвалится

Запасной путь на случай, если Steam отзовёт ключ или перестанет его выдавать:
у сообщества есть XML-эндпоинты, которым ключ не нужен —
`https://steamcommunity.com/id/<ник>/games?tab=all&xml=1` отдаёт список игр
с часами, а `https://steamcommunity.com/id/<ник>/?xml=1` — профиль и аватар.
Работает только для открытых профилей и отдаёт меньше полей (нет активности
за две недели), но статистику собрать хватит. Сейчас это не используется —
основной путь официальный Web API.
